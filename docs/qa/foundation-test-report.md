## Failures and cause

No test fails in the final run. These are the issues of the phase, with their cause and fix:

| # | Symptom | Cause | Fix |
|---|---|---|---|
| 1 | The substitution in `tsconfig.json` had no effect | The CLI generated the files with CRLF on Windows and the pattern looked for `\n` | Pattern `\r?\n`. Then the whole of `frontend/` was converted to LF (Prettier and a script), as `.gitattributes` requires (`eol=lf`) |
| 2 | `ng build`: TS2322 in `wizard-screens.ts` | `TextGroup<K>` is covariant in `K` because of `missing: readonly K[]`, so a group with more keys is not assignable to `TextGroup<'title'>` | Generic helper `titleOf<K>(group: TextGroup<K \| 'title'>)` |
| 3 | `ng build`: TS2322 in `strapi-dto.ts` (`asDto`) | TS cannot prove that `Readonly<Record<string, unknown>>` fits the mapped type `Dto<K>` with a generic `K` | Documented assertion: it is safe because every attribute of `Dto<K>` is optional and `unknown` |
| 4 | `ng build`: TS2345 in `create-quote-number.ts` | With TypeScript 6, `crypto.getRandomValues` requires `ArrayBufferView<ArrayBuffer>`, and `Uint8Array` without a parameter is `Uint8Array<ArrayBufferLike>` | `RandomFill = (target: Uint8Array<ArrayBuffer>) => void` |
| 5 | When generating the placeholder pages with sed, every line started with a backtick | In GNU sed, `` \` `` is the start-of-buffer anchor, not a literal backtick | Files rewritten without sed |
| 6 | The AC-02.8 test had a literal U+00A0 instead of the `\u00A0` escape | The initial write of the file left the real character, which is invisible and fragile (it was not Prettier: `prettier --check` accepts the escape) | Explicit escape restored. `grep` of the bytes `c2 a0` in `src/`: no results |

**Checks on the tests themselves** (so that green on the first try does not hide tests that check nothing):

- Mutation: changing the February 29 birthday in `age-in-years.ts` from `{ month: 3, day: 1 }` to `{ month: 2, day: 28 }` makes exactly `age-in-years.spec.ts › REQ-01.20 someone born on 29 February …` and `legal-age.spec.ts › AC-01.18 today 2026-02-28, birth date 2008-02-29 → valid=false` fail. Then the code was restored and the whole suite was run again (result above).
- Time zone: the machine might already be in `America/Bogota`, so the control test with `Asia/Tokyo` shows that `vi.stubEnv('TZ', …)` really changes the local date in the Vitest *pool*. This closes the risk that ADR-0007 left open ("not run yet").
